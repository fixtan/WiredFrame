# 画像タイルのテクスチャ読み込み（v0.2.1）

6 画面などで起動が重いのは、タイル 1 枚ごとに画像を読んで GPU に載せていたため（`cols × rows` 枚 × モニター数）。

## 常に効く（画質は変わらない）
- 同じ画像は 1 回だけ読み、同じ画像のタイルでテクスチャを共有する（`TileMode.makeTextureLoader`）。
- 読み込みは同時に 3 枚まで。タイルの並び順に読むので、画面の手前から順に出る。
- 共有テクスチャは `disposeTiles` でまとめて 1 回だけ解放する（タイルごとには解放しない）。

## 設定「画像を軽くする」（`imageMaxSize`、モニターごと）
- 0 = OFF（元の画質。異方性フィルタ 16）。
- 2048（初期値）/ 1024 / 512 = 長辺をその値まで縮小して読む（異方性フィルタ 4）。
- 実装: `fetch` → `createImageBitmap`（`resizeQuality: 'high'`、`imageOrientation: 'flipY'`）。ImageBitmap は GPU で反転できないので、`flipY = false` にしている。
- 変えるとタイルを作り直す（`appearance` に含めている）。
- 保存値に無い場合は 0 になる（`settings.ts` の既定値で補う）。

## 確認したこと
- 型チェック、`vite build`、Chromium で `createImageBitmap` の縮小と上下反転を確認。
## 実機（6 画面・12700K + RTX 4070 Ti）
- OFF のとき、起動時に一瞬フリーズしていたのが、共有と同時読み込みの制限でなくなった。
- 1024 は明らかに軽く、2048 も軽い（1024 より少し重い）。そのため初期値を 2048 にした。
- 画像は、全モニターで順番に並んでいく（同時 3 枚までの制限のため）。
- GPU 使用率は、画像タイルだけだと、実行前後でほとんど差が分からない（GPU 15%、専用メモリ 5.7GB 前後）。
