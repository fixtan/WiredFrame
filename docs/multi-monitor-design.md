# WiredFrame マルチモニター設計メモ（2026-10-12）

`docs/multi-monitor-design.md` に置く想定。「事実（コードから）」「決定（ユーザー）」「提案・仮定（Claude）」「要検証」を分けて書く。

## 1. 現状の事実（コードを読んだ範囲。実機未確認）

- 各モニターのウィンドウは独立した webview。`AppManager` / `TileMode` / Three のシーン / Clock をウィンドウごとに持つ。
- サブモニターは Rust の `open_sub_monitors`（`src-tauri/src/lib.rs`）が起動時に1回だけ生成する。ラベルは `sub-monitor-{index}`。main があるモニターは除外。
- 設定は `localStorage`（キー `wiredframe_settings_v1`）。読むのは各ウィンドウの起動時の1回だけ。
- 設定モーダルは `index.html` の `#settings-modal`。サブウィンドウも同じ `index.html` を読むので、モーダルはどのウィンドウにも存在する。
- トレイ「設定」→ Rust が `emit_to("main", "open-settings")` → main の `listen` でモーダルを開く（2026-10-12 に全モニターに出る不具合を修正済み）。
- `TileMode.rebuildTiles()` は `totalTiles = 60`、`cols = 10`、`rows = 6` が固定値。`calcSpherePosition` も 60 前提。縦画面だと 10 列は収まらない。
- カメラは `position.z = 30`、FOV 60 固定。アスペクト比によるグリッドのフィット調整はない。
- `group.clear()` は geometry / material / texture を dispose しない。60 枚が同じファイルを別々にテクスチャ化している。
- `src/modes/NoiseMode1.ts` / `NoiseMode2.ts` は空ファイル（0 行）。`IMode` はある。
- タイルアニメ 9 種（`tile-animations/`）の中身は未読。縦画面での見え方は未確認。

## 2. 決定（ユーザー）

- 各モニターで独立して設定する。全モニターをまたぐ 1 枚の大きなシーンにはしない（モニターの大きさがバラバラで不自然になるため）。
- モニター別にする項目：アニメーション（再生モード・固定パターン・切替間隔）、タイルサイズ、縦横の並べ方、背景（色・画像）。縦画面のモニターがあるため。
- 設定UI：トレイの「設定」で、各モニターに専用の設定パネルを表示する。そのモニターで設定を変えると、そのモニターに即反映されて確認できる。
- 保存：パネルで保存すると、そのモニターの設定だけ保存され、次回起動時に反映される。
- main の設定を閉じると、全部の設定パネルが閉じる。
- 未保存のときの確認ダイアログは作らない（作るのが面倒なので。後で足してもいい）。
- 将来、ノイズ記事のようなシェーダーアニメも表示できるようにしたい（今は考えなくていい）。
- テクスチャの軽量化（縮小して 1 枚の絵にまとめて分割表示、Protocol Atlas 方式）は後回し。

## 3. 提案・仮定（Claude。ユーザーの確認待ちを含む）

### 3.1 スキーマ v2

```ts
// 共通（main の設定パネルだけに出す）
type GlobalSettings = {
  targetDir: string;     // 画像フォルダ。仮定：共通のまま。モニター別にしたくなったら monitor 側に上書きを足す
  multiMonitor: boolean;
};

// モニター別（各モニターの設定パネルで編集）
type MonitorSettings = {
  playMode: 'rotation' | 'random' | 'fixed';
  fixedPattern: string;
  intervalSec: number;
  tileSize: number;
  cols: number;          // 新規。現状は 10 固定
  rows: number;          // 新規。現状は 6 固定
  spacingX: number;
  spacingY: number;
  bgColor: string;
  bgImagePath: string;
};
```

- 保存キーを分ける：`wiredframe_global_v2` と `wiredframe_monitor_v2:<monitorKey>`。1つのJSONを複数ウィンドウが読み書きすると上書きし合う恐れがあるため。
- 移行：旧 `wiredframe_settings_v1` が残っていて v2 がない場合は、その値を全モニターの初期値にする。
- 将来シェーダー系を足すときは、`MonitorSettings` に `mode` を足す形にする（今は足さない）。シェーダー系は `IMode` の別実装にするのが自然だと思う。

### 3.2 設定パネルの動き

1. トレイ「設定」→ Rust が全ウィンドウに `open-settings` を broadcast（`emit_to("main")` をやめる）。
2. 各ウィンドウが、自分のモニターの設定にひも付いたパネルを開く。main のパネルだけ共通設定の欄（画像フォルダ・マルチモニター）も表示。
3. 入力を変えると、そのウィンドウにだけライブプレビュー（保存はしない）。
4. 保存：自分のモニターのキーにだけ書き込んで、自分のパネルを閉じる。
5. キャンセル：保存済みの状態に戻して閉じる。
6. main のパネルを閉じる（保存・キャンセル・×）→ `close-settings` を broadcast。サブ側のパネルも閉じ、未保存のプレビューは破棄して保存済みに戻す（確認ダイアログなし）。ここは仮定。
7. 共通設定が変わったら `global-settings-changed` を broadcast。各ウィンドウが画像フォルダを再読み込みする。

### 3.3 縦画面対応

- `cols` / `rows` を設定にして、`totalTiles = cols × rows` にする。
- グリッド全体が画面に収まるように、アスペクト比からカメラ距離を計算するオプションがあると楽（提案）。
- 9 種のアニメが縦画面で破綻しないかは、実機で見て確認する。

## 4. 実装順

1. モニター識別の確認：起動時に `available_monitors` の name / position / size / scale をログ出力し、6枚の区別方法（保存キー）を決める。
2. `settings.ts` を切り出す：スキーマ v2、読み書き、旧設定の移行。
3. 設定パネルをモニター別に：`open-settings` の全ウィンドウ化、ライブプレビュー、保存/キャンセル、`close-settings`。
4. `TileMode` の `cols` / `rows` 可変化と、縦画面向けのカメラフィット。
5. マルチモニター ON/OFF の即時反映（サブウィンドウの生成・破棄）、モニター構成が変わったときの再展開。
6. 後回し：テクスチャの dispose と共有・縮小・アトラス化、シェーダーアニメ、時間同期、未保存の確認ダイアログ。

## 5. 要検証

- モニターの一意な識別：Windows のディスプレイ番号（設定アプリの 1〜6）と Tauri が返す順番・name が一致するかは不明。構成変更後にキーが変わらないかも確認する。
- `localStorage` が main とサブウィンドウで共有されるか（同じ WebView2 のデータフォルダなら共有されるはずだが、未確認）。共有されないなら、Rust 側でアプリデータフォルダの JSON ファイルを読み書きする方式に変える。
- 全画面のサブウィンドウ上でフォルダ選択ダイアログ（`open`）が前面に出るか。後ろに隠れる場合は対策が必要。

## 6. 後回しにした軽量化メモ

- 保存時に画像とタイルが決まったら、縮小して 1 枚（または数枚）のアトラスにまとめ、UV で分割表示する案。Protocol Atlas と同じ発想で、テクスチャ数が減って負荷が下がるはず（効果は未計測）。
- 決める点：アトラスをどこで作るか（Rust 側か、ブラウザの canvas で作ってキャッシュ保存か）。モニターごとにタイル数・サイズが違うので、アトラスをモニター別に作るか、共通の縮小画像セットを各ウィンドウで使うか。
- 6 ウィンドウは GPU コンテキストが別でテクスチャを共有できないので、ウィンドウ数だけメモリが増える。
