# ノイズモード（v0.2.0）

`src/modes/NoiseMode1.ts`。元は別プロジェクトの「Curl Noise × Audio」(Three.js + GPGPU)。
WiredFrame 用に次のように変えた。

## 仕組み
- 粒子の位置・寿命を GPU のテクスチャ（`GPUComputationRenderer`）に持つ。1 フレームごとに、各粒子をカールノイズの流れ場で動かす。
- 描画は `THREE.Points`。頂点は位置テクスチャを読んで座標を決める（CPU は粒子を触らない）。
- 寿命が尽きた粒子は初期配置（球の中）に戻る。寿命の残りで色を変え、生まれたては明るい芯の色になる。

## 元との違い
| 元 | WiredFrame |
|---|---|
| 音（FFT の低・中・高域）で動く | 音は無し。内部の LFO（呼吸＋ときどき膨らむ）で代用。音が無い方が綺麗だったので控えめ |
| 色は GUI で固定 | 色相が `COLOR_CYCLE_SEC`（150 秒）で一周。芯の色は +0.2 ずらす |
| lil-gui（インスペクター） | 設定パネルの「詳細な調整」に置き換え（下記）。調整値は `src/modes/params.ts` |
| OrbitControls の自動回転 | 粒子群を `ORBIT_SEC`（40 秒）で回す |
| フレームごとの固定ステップ | `u_dt`（60fps 基準）で時間補正。FPS 上限で間引いても速さが変わらない |
| 粒子サイズ px 固定 | 画面の高さに比例（`REF_HEIGHT` = 1400 を基準）。解像度が違うモニターで見た目を揃える |

## 設定（モニターごと）
`MonitorSettings` に追加: `mode`（`tiles` / `noise1`）、`noiseSize`（粒子テクスチャの一辺。256 / 384 / 512）、`fps`（上限）。
- 明るさ（`brightness`）はタイルと共通。ノイズでは色に掛ける（ガンマ 2.2）。
- 粒子数 = `noiseSize`²。標準 384 → 約 15 万、512 → 約 26 万。
- 既定は `tiles` / 384 / 60。古い保存値には `mode` が無いので `tiles` になる（既存の設定は壊れない）。

## 詳細な調整（モードごとのパラメータ）
設定パネルの「詳細な調整」（ノイズモードのとき）に、粒子の大きさ・流れの速さ・渦の大きさ・寿命・脈動・色と回転の周期のスライダーが出る。
動かすとその場でプレビューされ、「適用して保存」でモニターごとに保存される（`modeParams.noise1`）。「この調整を初期値に戻す」で既定値に戻る。
色・回転の周期は、変えても色や向きが飛ばないよう、時間ではなく積算で持っている。
仕組みと新モードへの足し方は `docs/new-mode.md`。

## 負荷の目安（6 モニターで動かす場合）
- 粒子 1 個あたり毎フレーム simplex noise を 18 回計算する（カールの差分 6 点 × 3 成分）。
- 目安: 15 万粒子 × 6 窓 × 30fps。重ければ「粒子の数」か「FPS 上限」を下げる。実機の GPU で要確認。
- サブモニターごとに `mode` を変えられる（例: メインはタイル、サブはノイズ）。

## モードの切り替え
`main.ts` の `applyToMode`。モード（またはノイズの粒子数）が変わったら、`AppManager.switchMode` で旧モードを `dispose` して新しく作る。
タイルに戻したときは、画像フォルダ・外観を読み直す。ノイズの開始に失敗した場合（浮動小数テクスチャ非対応など）は、タイルに戻してログに出す。

## 検証メモ
- ヘッドレス Chromium（SwiftShader）で、描画・モード切替・保存を確認済み。ソフトウェア描画なので動きの速さ・見た目の最終確認は実機。
- 未確認: Windows 実機での 6 画面の負荷、縦画面（1200x1600）での見え方。

## 今後
- ノイズ4 以降は、元ネタが見つかったものから `NoiseMode4.ts` … として足す（手順は `docs/new-mode.md`）。
- ノイズの色相の速さ・渦の大きさを設定にするかは、実機で見てから。

# ノイズ2: Mandelbulb（`NoiseMode2.ts`）

元ネタ: [Noise #60] Mantra in Mandelbulb（`/gallery/audiovisualart/`）。Mandelbulb（3D フラクタル）をレイマーチングで描き、虹色に光らせる。

## 元との違い
- 音・グリッチ・VR・lil-gui を外した。形のゆっくりした回転と、上から降ってくる粒は残した（光る・揺れる演出は無し）。
- 回転は OrbitControls の自動回転ではなく、カメラを原点の周りで回す（見下ろしの角度は元の (0,2,3) と同じ）。
- 色の変化（`uTime * 0.2`）は積算の位相にした。速さを変えても色が飛ばない。
- 元のレイマーチング（距離関数・法線・パレット）はそのまま。ステップ数と反復回数だけ uniform にして調整できるようにした。

## 負荷と、軽くする調整
負荷は粒子数ではなく**画面の解像度**に比例する（全ピクセルでレイを飛ばす）。次を「詳細な調整」で下げると軽くなる。
| 項目 | 既定 | 効果 |
|---|---|---|
| 描画の解像度 | 0.5 | 内部の解像度の倍率。0.5 で約 1/4 の計算量。CSS で引き伸ばす（`AppManager.setRenderScale`）。**いちばん効く** |
| レイの最大ステップ数 | 70 | 小さいと細部が欠け、ざらつく |
| フラクタルの反復回数 | 5 | 小さいと形が単純になる |
| 光のにじみ | 0.5 | 0 でブルームのポストエフェクトを丸ごと省く |
| 降ってくる粒の数 | 2000 | 負荷は小さい |

そのほか: 形の複雑さ（power）、虹色の強さ、色の変わる速さ、一周する秒数、カメラの距離。
描画解像度は、モードを切り替えるたびに 1 に戻る（`AppManager.switchMode`）。

## 仕組みの追加（共通）
- `IMode.getRenderScale()`: 描画解像度の倍率。`main.ts` が `manager.setRenderScale` に渡す。
- `IMode.render(renderer)`: 描画を自前で行う（ブルームなどのポストエフェクト用）。

## 検証メモ
- ヘッドレス（SwiftShader）で、描画・モード切替・保存・解像度の倍率（内部 320x200 / 表示 640x400）を確認。
- 未確認: 実機の負荷（特に 3840x1600 や 6 画面）。重ければ、まず描画の解像度を下げる。

# ノイズ3: ワイヤーフレーム地形（`NoiseMode3.ts`）
元ネタ: [Noise #57] Audio-Reactive Domain Warping（`PlaneGeometry` の頂点を fbm ノイズで持ち上げ、高さで 2 色を混ぜる）。

## 元との違い
- 音・FFT 表示・VR・lil-gui は外した。ノイズの時間スクロール（波打ち）、平面の回転、高低の色分けは元のまま。
- 音が無いと起伏が緩やかなので、`山の高さ`（既定 1.5）・`細部の層の数`・`細部の強さ`・`うねり`（振幅が約 10 秒周期で増減。0 でオフ）を足した。
- 色は元の 2 色（#2c58af 青 / #1d771e 緑）を HSL にして、色相・鮮やかさ・明るさ・高い所の色の出方・高低の差で調整する。ShaderMaterial は linear のまま出力するので、HSL は sRGB として解釈して元と合わせている。
- ノイズは平面の UV ではなく**ワールドの位置**で引く。範囲（`地形の範囲`）を変えても山の大きさは変わらず、広げると山が増える。

## 範囲を広げたときの負荷
- 負荷は頂点数（分割数の 2 乗）にほぼ比例する。既定は 範囲 24 × 分割 320（約 10 万頂点、元は 18 × 256 = 約 6.6 万）。
- 同じ分割数で範囲だけ広げると、格子が粗くなる（範囲 120 × 分割 512 だとだいぶ粗い）。細かさを保つなら分割数も増やす必要があり、その分重くなる。
- 遠くを見せるだけなら「霧で消える距離」で黒に溶かして端を隠すのが安い。範囲の半分くらいにすると端が見えない。
- 範囲・分割数を変えるとジオメトリを作り直す（スライダーを動かすたびに作り直すので、保存前の試行では少しもたつくことがある）。

## 検証メモ
- ヘッドレス（SwiftShader）で、既定と 範囲 120 / 分割 512 の描画を確認。
- 未確認: Windows 実機の負荷（3840x1600、6 画面）、縦画面での見え方、範囲・分割数を大きくしたときの重さ。

# マウス操作（ノイズ1・2・3 共通）
- すべて `OrbitControls`: ドラッグで回転、ホイールで拡大縮小。ノイズ1・2 は何もしなければ自動で回り続ける（「自動回転で一周する秒数」）。ノイズ3 は地形のほうが回る（「地形の回転の速さ」）ので、カメラは自動で回らない。ノイズ3 のカメラは地面より下には回り込めない。
- 「カメラの距離」スライダーは、動かしたときだけカメラの距離を上書きする。ホイールで変えた距離は、他のスライダーを動かしても保たれる。
- 最初の実装では OrbitControls を外していた（スクリーンセーバーでは回す機会が少ないと判断した）が、好きな角度・大きさにできるので戻した。

# 無操作起動のセーバーの終了（ESC のみ / 操作で終了）
- 共通設定「自動で起動したセーバーは、キー・マウス操作で終了する」（`idleExitOnInput`、既定 OFF）。
- OFF のときは ESC だけで終了する。マウスを動かしても終了しないので、画面を回せる。
- 自動起動ではウィンドウにキーボードのフォーカスが来ないことがあるため、ESC は `idle.rs` の `watch_esc` が `GetAsyncKeyState(VK_ESCAPE)` で 0.05 秒おきに見張る（起動後 2 秒の猶予あり）。
- ON のときは、従来どおり `watch` が `GetLastInputInfo` で操作を見て終了する。
- 手動起動（ホットキー・トレイ）は従来どおり ESC のみ（画面側のキー入力）。
- 未確認: Windows 実機での、自動起動後の ESC 終了（Linux では `cargo check` までしか確認できない）。
