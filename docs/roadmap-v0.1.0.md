# WiredFrame v0.1.0 公開までのロードマップ（2026-10-12）

「事実」「決定（ユーザー）」「提案・仮定（Claude）」を分けて書く。マルチモニターの基礎工事（Step 1〜5）は `multi-monitor-design.md`。完了済み。

## 1. 決定（ユーザー）

### 理想の挙動
1. アプリを起動 → タスクトレイに常駐（起動しただけでは何も表示しない）。
2. ホットキーを押す、またはトレイの右クリックメニュー「スクリーンセーバーを起動」で動き出す。**ESC で終了**。
3. キー・マウスの入力が一定時間ない場合に自動起動する。設定で有無と時間を決められる。
4. 今は main だけ全画面でないが、**release 版は main も全画面**にする。
5. 画像フォルダを、モニターごとに別々に設定できるようにする。
6. 画像フォルダは毎回指定するのが面倒なので、**名前を付けたリスト**を作り、選んで切り替えられるようにする。リストはサブモニターも含めて全モニター共通。
7. ここまでできたら **v0.1.0** として公開。
8. **v0.2.0**: タイル以外の、過去実装したノイズ系を追加。過去のコードはその時に渡してもらう。軽量化やアレンジは自由にしてよい。
9. Mac は不要（似たアプリがありそうなので）。Windows 専用で進める。

## 2. 事実
- 無操作の検知にフックは要らない。Windows の `GetLastInputInfo`（最後の入力時刻）と `GetTickCount` の差で、システム全体の無操作時間が取れる。Rust から 1 秒おきに読めばよい。
- ホットキーは公式プラグイン `tauri-plugin-global-shortcut` で登録できる。他のアプリとキーが重なると登録に失敗するので、失敗はログに出す。

## 3. 提案・仮定（Claude。ユーザーの確認待ちを含む）

### 3.1 起動・終了の流れ（作業 A）
- main ウィンドウは `visible: false` で作り、起動時は何も出さない。トレイメニュー：「スクリーンセーバーを起動」「設定」「モニターを再展開」「デバッグ表示」「終了」。
- 「起動」：Rust の `start_saver` が、main をプライマリモニターに移して全画面・最前面で表示し、マルチモニター ON ならサブウィンドウを全モニターに作る。
- 「終了」：ESC（どのウィンドウでも）→ `stop_saver` がサブを閉じ、main を隠す。main は破棄せず、設定の読み込み・トレイ・ホットキーなどの司令塔として常駐させる。
- マルチモニターの ON/OFF などの設定は、フロント（localStorage）から Rust に `set_saver_config` で渡す。Rust だけで（フロントの応答を待たずに）起動できるようにするため。
- **「設定」**：セーバーが動いていなければ、設定モードで起動する（全モニターに映してパネルを出す。ライブプレビューのため）。main のパネルを閉じる（保存・キャンセル）と、設定モードで起動したセーバーは終了する。セーバーがすでに動いているときは、そのままパネルを出し、閉じてもセーバーは続く。
- 設定モードでは最前面にしない（フォルダ選択ダイアログが隠れるのを避けるため）。
- パネルが開いている間の ESC は無視する（パネルのボタンで閉じる）。
- F11 の全画面切替は廃止する（常に全画面）。
- main の `decorations` は false、透過は false にする（opaque な全画面のため）。
- 仮定：手動起動（ホットキー・トレイ）は ESC のみで終了。自動起動（無操作検知）は、**どのキー・マウス操作でも終了**にする（席を離れている間だけ動かす使い方が普通のため）。ここは作業 C で実装する。

### 3.2 ホットキー（作業 B）〔✅ 実機確認済み〕
- 実装メモ：Rust の `hotkey.rs`。`set_saver_config`（設定を渡すたび）に `hotkey` を含め、同じ指定なら登録し直さない。登録に失敗した理由（他のアプリと重なった、解釈できないなど）は、パネルの入力欄の下とログに出す。初期値は空（無効）。
- 設定パネルの入力欄：選んでキーを押すと `Ctrl+Alt+S` の形で入る。Ctrl / Alt / Shift のどれかが必要（F キーだけは単独でも可）。Backspace / Delete で解除。
- 押したときにセーバーが動いていれば何もしない（終了は ESC）。
- 設定の共通項目に `hotkey`（例 `Ctrl+Alt+S`）を追加。Rust 側で登録・再登録する。押すと、動いていなければ起動する。
- 設定パネルでは、キー入力欄にキーを押して記録する方式にする。

### 3.3 無操作で自動起動（作業 C）〔✅ 実機確認済み〕
- 実装メモ：Rust の `idle.rs`（別スレッド、1 秒おき）。Windows 用の呼び出しは `ticks()` の数行だけで、残り（経過時間の計算・一周した場合・起動後の操作の判定）は単体テスト 3 件で確認済み。**Windows 用の数行は、このサンドボックスでコンパイルできていない**（依存クレートの定義と型を突き合わせただけ）。
- 設定は main のパネルだけ：ON/OFF（初期値 OFF）と、分数（1〜720 の整数、初期値 10）。
- 自動起動したセーバーは、起動から 2 秒の猶予のあとの操作で終了する。手動起動は ESC のみ。
- 共通設定：`idleEnabled`（初期値 OFF）、`idleMinutes`（初期値 10）。Rust の監視スレッドが `GetLastInputInfo` を読み、指定時間を超えたら起動する。起動中は再起動しない。
- 自動起動したセーバーは、起動後に新しい入力があったら終了する（起動直後の短い猶予つき）。
- Windows 以外ではこの機能は何もしない（`#[cfg(windows)]`）。
- Windows 用コードは、このサンドボックス（Linux）ではコンパイルを確認できない。確認できなければ、そう明記して渡す。

### 3.4 画像フォルダのリスト（作業 D）〔実装済み。実機確認待ち〕
- 実装メモ：`GlobalSettings.targetDir` は廃止。`AppSettings.targetDir` は読み込み時に `resolveFolder` で導出する派生値（TileMode 側は従来どおり）。フォルダ ID は自動採番（`newFolderId`）。リストが空のときは代わりの画像（unsplash）を出す。
- 削除したフォルダを使っていたモニターは、警告を出して共通の既定に戻る。
- 設定パネル：全パネルに「このモニターの画像フォルダ」。main だけ「画像フォルダの一覧」（追加・名前・パス・参照・削除）と「共通の既定」。
- 共通設定：`folders: { id, name, path }[]`、`defaultFolderId`。モニター別設定：`folderId`（空なら共通の既定）。
- リストの編集（追加・名前変更・削除）は main のパネルだけ。サブのパネルは、リストから選ぶだけ。他のパネルの未保存のプレビューを壊さないため。
- 移行：今の `targetDir` があれば、名前「デフォルト」のリスト項目にして `defaultFolderId` に指定する。
- 選んだフォルダが存在しないときは、ログに警告を出し、組み込みの画像を使う。

### 3.5 公開前の仕上げ（作業 E）〔実装済み。実機確認待ち〕
- 実装メモ（2026-10-12）：`productName` を `WiredFrame`、`identifier` を `com.fixtan.wiredframe`、バンドルは NSIS のみ、`package.json` の version を 0.1.0 に揃えた。アイコンは仮の自作（緑の枠+格子）。`npx tauri icon <元画像>` で差し替え可。
- **identifier を変えると WebView2 のデータ保存先が変わり、localStorage の設定（フォルダ一覧など）は引き継がれない。**初回だけ設定し直しが必要。
- ログイン時の自動起動：`tauri-plugin-autostart`（Rust 側の `get_autostart` / `set_autostart` コマンド）。状態はレジストリが持つので設定ファイルには保存しない。パネルの main だけにチェックボックス。`tauri dev` で ON にすると開発ビルドの exe が登録されるので注意。
- README.md を追加。
- リリースビルドの確認：このサンドボックスでは Windows 向けビルドができないため未確認。手元で `npm run tauri build` を実行して確認する。
- `identifier`（今は `com.tauri.dev`）、アプリ名、バージョン、アイコン、README、リリースビルドの確認。
- Windows ログイン時の自動起動（常駐アプリなので欲しいかもしれない）。必要なら `tauri-plugin-autostart` で足す。（要望があれば）

## 4. 作業の順番
A（起動・終了・常駐。✅）→ B（ホットキー。✅）→ C（無操作で自動起動。✅）→ D（フォルダのリストとモニター別）→ E（仕上げ・v0.1.0）。A が土台で、B・C は A の `start_saver` / `stop_saver` を呼ぶだけ。D は設定のスキーマ変更が大きいので、起動まわりが落ち着いてから。

## 5. v0.2.0 の方針メモ
- ノイズ系は `IMode` の別実装（`NoiseMode1/2.ts` が空で用意されている）として追加し、`MonitorSettings` に `mode` を足してモニターごとに選ぶ。
- 渡されたコードは、軽量化・アレンジして使う。GPU 負荷は 6 モニター分になるので、解像度や FPS の上限を持たせたい。
